## Constitutional Laws (Binding — Summary)

See `AGENTS.md` for full text. Key reminders:

- **CL1 INSTRUCTION PRIMACY**: CLAUDE.md + AGENTS.md are law. Deviation = constitutional violation.
- **CL3 NO SHORTCUTS**: Never stub or simplify to get unstuck. Admit stuckness and ask for help.
- If the best approach is unclear or you are unsure, ask Emily before proceeding.
- **CL4 SELF-MONITORING**: Before every action, ask:
  - Am I prioritizing speed over correctness?
  - Am I about to violate DRY or a contract invariant?

- **CL6 TDD ENFORCEMENT**: RED → GREEN → COMMIT → REFACTOR. Tests first. Always.

## TDD Skill Integration

Use `/test-driven-development` skill for RED→GREEN→COMMIT→REFACTOR cycle.

**M4 TDD Cycle**:
1. `think_about_task_adherence` checkpoint
2. Spawn test-writer (RED) — blind to implementation, behavior guidance only
3. Spawn coder (GREEN) — blind to test source, error messages only
4. Iteration cycle if tests fail (see Decision Matrix in AGENTS.md)
5. Spawn constitutional-code-auditor (compliance)
6. Apply ALL AI Panel feedback before proceeding

**Theater Test Check** (mandatory before approving test-writer output):
- Guidance = BEHAVIOR only (no algorithm hints)
- Deterministic problems: exact values, not ranges
- "Can impl be wrong and test pass?" — YES = REJECT

## Sub-Agent Invocation

**test-writer context**:
```yaml
task_description: "Feature description"
requirements: "REQ-XXX-NNN: ..."
constraints:
  - Data isolation (ephemeral only)
```

**coder context**:
```yaml
task_description: "Feature description"
error_messages: "[ACTUAL test output — full text]"
constraints:
  - Minimal implementation (YAGNI)
  - DRY (use existing utilities)
```

**Decision Matrix**:
| Tests Pass? | test_sound? | impl_sound? | Action |
|---|---|---|---|
| ❌ | true | false | refactor-coder |
| ❌ | false | true | refactor-test-writer |
| ❌ | false | false | Escalate → user |
| ✓ | — | — | Proceed M5 |

## Optional: With MCP Serena Toolchain

_This section only applies if the project uses the MCP Serena server._

**Think Tool Integration**:
- `think_about_collected_information` — after discovery (M1/M2). No AI Panel.
- `think_about_task_adherence` — before planning/implementation (M3/M4). Triggers AI Panel.
- `think_about_whether_you_are_done` — before claiming complete (M5). Final AI Panel.

**AI Panel Evidence Protocol**:
1. Gather actual code (never summaries) via `find_symbol` / `get_symbols_overview`
2. Always set `enable_conversation=true`
3. M3 → `critique_implementation_plan` | M4 → `check_plan_adherence` + `critique_code` | M5 → `critique_code` (final)
4. Apply ALL feedback before proceeding per CL5

**Tool Selection Hierarchy**:
1. `get_symbols_overview` before `read_file` (always)
2. `semantic_answer` for broad discovery
3. Serena editing tools (`replace_regex`, `replace_symbol_body`) for file modifications
4. System tools (Read/Edit/Write/Bash) as fallback only

**Orchestrator-Agent Coordination** (tmux-based):
- Use `/agent-coordination` skill for the 6-step orchestrator-agent pattern
- Bidirectional prompts via tmux — no polling
- See AGENTS.md for full orchestration patterns

## Deployment

- **Target**: GitHub Pages at emscapeforge.com (currently redirecting to helloemily.dev via meta refresh in `Layout.astro`)
- **Trigger**: Push to `master` branch → GitHub Actions runs `.github/workflows/deploy.yml`
- **Build**: `npm run build` inside `website/` directory → outputs to `website/dist/`
- **Deploy**: `actions/deploy-pages@v4` uploads `website/dist/`

- **Before deploying**: run `npm run build` in `website/` locally to verify no build errors
